上一章讲了学术内容集合（论文、演讲、作品集、教学），那些是"一条一条的内容"。这一章讲的是驱动网站结构和展示的数据文件——`_data/`、`_pages/`、`_includes/`。

## 4.1 `_data/` — 导航、作者、CV 的配置

`_data/` 目录放的是 YAML 格式的数据文件，Jekyll 会自动加载它们，模板里通过 `site.data.文件名` 来读取。

你的项目里有 5 个文件：

### `navigation.yml` — 导航栏

控制顶部导航栏显示哪些链接。目前的配置：

```yaml
main:
  - title: "首页"
    url: /
  - title: "文章"
    url: /year-archive/
  - title: "项目"
    url: /portfolio/
  - title: "关于"
    url: /about/
```

想加一个"简历"链接？取消注释或新增一条就行：

```yaml
  - title: "CV"
    url: /cv/
```

**删掉某条链接不会删除页面**，只是导航栏不显示了。页面本身还是可以通过直接访问 URL 打开的。

### `authors.yml` — 多作者支持

如果你的网站有多个作者（比如实验室共同维护），在这里定义每个作者的信息。单人网站只需要保持默认的示例就行，不用太关注。

### `cv.json` — JSON 格式的简历数据

一个标准的 JSON Resume 格式文件，包含 `basics`（基本信息）、`education`（教育经历）、`work`（工作经历）等字段。配合 `_pages/cv-json.md` 和 `_layouts/cv-layout.html` 可以渲染出结构化的简历页面。

如果你选择直接用 Markdown 写简历（`_pages/cv.md`），这个文件可以不管。

### `ui-text.yml` — 界面文字

控制网站上各种按钮和提示文字的多语言版本。比如"Read more"、"Published:"、"Categories"这些文字的中文翻译就在这里。一般不需要改，除非你想把界面全部中文化。

### `comments/` — 评论数据

如果你开启了 Staticman 评论系统，用户提交的评论会以 YAML 文件的形式存在这个目录下。

## 4.2 `_pages/` — 独立页面

`_pages/` 存放不属于任何集合的独立页面。你的项目里有 19 个文件，但常用的就这几个：

| 文件 | 作用 |
|---|---|
| `about.md` | 首页/关于页（用了 `splash` 布局，是个精心设计的落地页） |
| `cv.md` | Markdown 简历页 |
| `cv-json.md` | JSON 简历页 |
| `publications.html` | 论文列表页（遍历 `site.publications`） |
| `talks.html` | 演讲列表页 |
| `portfolio.html` | 作品集列表页 |
| `teaching.html` | 教学经历列表页 |
| `404.md` | 404 页面 |
| `sitemap.md` | 站点地图 |
| `year-archive.html` | 按年份归档 |
| `tag-archive.html` | 按标签归档 |
| `category-archive.html` | 按分类归档 |

### 页面的 frontmatter

`_pages/` 里的文件也是带 frontmatter 的，常用字段：

```yaml
---
layout: archive           # 布局类型
title: "Publications"
permalink: /publications/ # 访问 URL
author_profile: true      # 是否显示侧边栏
---
```

`permalink` 决定了这个页面的 URL。比如 `permalink: /cv/` 就是 `https://你的用户名.github.io/cv/`。

### 列表页怎么工作

拿 `publications.html` 举例，核心代码就几行：

```liquid
{% for post in site.publications reversed %}
  {% include archive-single.html %}
{% endfor %}
```

遍历所有论文，每篇用 `archive-single.html` 组件渲染一个卡片。`reversed` 让最新的排在前面。其他列表页（talks、teaching、portfolio）结构完全一样。

## 4.3 `_includes/` — 可复用的页面组件

`_includes/` 里是 35+ 个 HTML/Liquid 片段，被 `_layouts/` 和 `_pages/` 通过 `{% include 文件名.html %}` 引用。

### 常用的 include 文件

| 文件 | 作用 |
|---|---|
| `head.html` | `<head>` 标签内容（CSS、meta、SEO） |
| `masthead.html` | 顶部导航栏 |
| `sidebar.html` | 右侧边栏（作者信息 + 页面目录） |
| `footer.html` | 页脚 |
| `author-profile.html` | 作者信息卡片（头像、简介、社交链接） |
| `archive-single.html` | 文章/论文的列表卡片 |
| `page__hero.html` | 文章顶部大图 hero 区域 |
| `scripts.html` | JS 脚本加载（jQuery、main.js 等） |
| `seo.html` | SEO meta 标签（Open Graph、Twitter Cards） |
| `cv-template.html` | 简历模板 |
| `tag-list.html` | 标签列表 |

### 子目录

`_includes/` 里还有一些子目录，按功能分组：

| 子目录 | 内容 |
|---|---|
| `head/` | `<head>` 的子组件（`custom.html` 可以添加自定义 CSS/JS） |
| `footer/` | 页脚子组件（`custom.html` 可以添加自定义页脚内容） |
| `analytics-providers/` | 各种统计分析服务（Google Analytics 等） |
| `comments-providers/` | 各种评论系统（Disqus、Staticman 等） |
| `nav_list/` | 导航菜单渲染 |
| `toc/` | 目录（Table of Contents）渲染 |
| `gallery/` | 图片画廊 |

### 自定义 include

最常自定义的是 `head/custom.html` 和 `footer/custom.html`。比如你想在每个页面加载一个自定义字体或添加一段 Google Analytics 代码，就加在 `head/custom.html` 里，而不是去改 `head.html`（这样以后更新模板不会丢失你的修改）。

## 它们之间的关系

```
_config.yml（全局配置）
    ↓ defaults
_data/（数据源）  →  _includes/（组件）  →  _layouts/（骨架）  →  最终页面
_pages/（独立页面）↗        ↑
_collections/（学术内容）↗
_posts/（博客）↗
```

简单说：`_data/` 提供数据，`_includes/` 提供组件，`_layouts/` 组装骨架，`_posts/`、`_pages/`、各 collections 提供内容。Jekyll 把它们拼在一起生成最终的 HTML。
