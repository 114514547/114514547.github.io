上一章我们鸟瞰了整个项目的目录结构。这一章深入 Jekyll 最核心的三个东西：`_config.yml`、`_posts/`、`_layouts/`。搞懂这三个，你就能自己改站点信息、写博客文章、理解页面是怎么渲染出来的。

## 2.1 `_config.yml` — 全站配置中心

打开项目根目录的 `_config.yml`，这是整个网站的"控制面板"。修改后需要**重启本地预览服务器**才能生效（`jekyll serve` 不会自动热加载这个文件）。

### 你需要优先改的几个字段

```yaml
title: "玻璃联邦的主页"        # 网站标题，显示在浏览器标签页和页眉
url: https://114514547.github.io  # 你的 GitHub Pages 地址
repository: "114514547/114514547.github.io"  # 仓库名
```

这三个字段决定了网站的基本身份。`url` 一定要写对，否则生成的链接全是错的。

### 作者信息块

`_config.yml` 里的 `author:` 部分会渲染到侧边栏。常用的字段：

```yaml
author:
  avatar: "profile.png"      # 头像，放 images/ 目录下
  name: "Wang"
  bio: "万里归船弄长笛，此心吾与白欧盟"
  location: "河南省郑州市"
  employer: "郑州大学"
  email: "w114514@gmail.com"
  github: "114514547"        # 只写用户名，不是完整 URL
  orcid: "https://orcid.org/yourorcidurl"
```

不需要的字段留空就行，侧边栏会自动隐藏对应的图标。比如你没有 Google Scholar 账号，`googlescholar` 那行保持注释或留空即可。

### 主题配色

```yaml
site_theme: "default"  # 可选: default, air, sunrise, mint, dirt, contrast
```

六种预设皮肤，改这一个词就能换整站配色。如果想深度自定义颜色，得去 `_sass/` 目录改 SCSS 文件（后面会讲）。

### defaults 段 —— 别忽略这个

`_config.yml` 最下面的 `defaults:` 段定义了"每种类型的内容默认带哪些配置"：

```yaml
defaults:
  - scope:
      path: ""
      type: posts        # 针对 _posts/ 里的文件
    values:
      layout: single     # 默认用 single 布局
      author_profile: true  # 默认显示作者侧边栏
      read_time: true    # 默认显示阅读时间
      comments: true     # 默认开启评论
```

这意味着你在 `_posts/` 里写文章时，不需要每个文件都重复写 `layout: single`，Jekyll 会自动套用这里的默认值。如果你发现某篇文章想单独关闭评论，在它自己的 frontmatter 里写 `comments: false` 就能覆盖默认值。

## 2.2 `_posts/` — 你的博客仓库

### 文件命名规则

`_posts/` 里的文件名**必须**遵守这个格式：

```
年年年年-月月-日日-标题.md
```

比如：
- `2026-05-23-github-pages简明教程.md` ✅
- `2026-5-23-tutorial.md` ❌（月份必须两位数）
- `my-post.md` ❌（没有日期前缀）

Jekyll 靠文件名里的日期来决定文章的发布时间。日期不对或者格式错误，文章就不会出现在网站上。

### Front Matter —— 文章的身份证

每个 `.md` 文件开头必须有一段 YAML front matter，用 `---` 包裹：

```yaml
---
title: "文章标题"
date: 2026-05-23T08:00:00.000Z
tags: ["Academic pages", "GitHub Pages", "Jekyll"]
categories: ["teaching"]
---
```

这是你告诉 Jekyll "这篇文章叫什么、什么时候发的、属于哪个分类"的地方。**如果省略了 front matter，Jekyll 会直接跳过这个文件，不会处理它。**

常用字段速查：

| 字段 | 作用 | 必填？ |
|---|---|---|
| `title` | 文章标题 | 是 |
| `date` | 发布日期 | 是（文件名里的日期和这里的要一致） |
| `tags` | 标签数组，如 `["Python", "教程"]` | 否 |
| `categories` | 分类数组，如 `["teaching"]` | 否 |
| `description` | 文章简介，用于 SEO | 否 |
| `header.teaser` | 列表页缩略图 | 否 |
| `header.overlay_image` | 文章顶部大图 | 否 |

### 草稿怎么写

还在构思的文章放 `_drafts/` 目录，文件名**不需要**日期前缀：

```
_drafts/
  my-unfinished-post.md    # 直接用标题命名
```

本地预览时加 `--drafts` 参数就能看到草稿：

```bash
jekyll serve --drafts
```

写好了之后，把文件**移到 `_posts/` 并加上日期前缀**，就能正式发布。

## 2.3 `_layouts/` — 页面骨架

`_layouts/` 目录决定了你的页面"长什么样"。你的项目里有 8 个布局文件，但日常你只需要了解其中几个。

### 布局继承关系

Academic Pages 的布局是**层层嵌套**的：

```
compress.html   ← 最底层，压缩 HTML 体积
  └─ default.html   ← 基础骨架：head、导航栏、页脚
        ├─ single.html    ← 文章/页面（你 90% 的内容用这个）
        ├─ archive.html   ← 归档列表页
        ├─ splash.html    ← 落地页/全屏封面
        ├─ talk.html      ← 演讲详情页
        └─ cv-layout.html ← 简历页
```

`default.html` 定义了每个页面共享的部分——`<head>` 标签、顶部导航栏（masthead）、页脚、JS 脚本加载。`single.html` 在它的基础上加上文章标题、正文、侧边栏、评论区。

你在 front matter 里写 `layout: single`，Jekyll 就会先渲染 `single.html`，它再调用 `default.html`，最后经过 `compress.html` 压缩输出。

### 默认布局不需要手写

还记得上一节的 `defaults:` 配置吗？`_posts/` 和 `_pages/` 都已经默认设了 `layout: single`，所以你写文章时 front matter 里**不用**再写 `layout`。

只有你想用特殊布局时才需要手动指定，比如你的简历页想用 CV 专用布局：

```yaml
---
layout: cv-layout
title: "我的简历"
---
```

### 布局里用到了 `_includes/`

打开 `single.html`，你会看到大量这样的代码：

```liquid
{% raw %}{% include head.html %}
{% include sidebar.html %}
{% include page__hero.html %}{% endraw %}
```

这些 `{% raw %}{% include %}{% endraw %}` 引用的是 `_includes/` 目录里的 HTML 片段。布局负责搭骨架，includes 负责填具体的组件——导航栏、侧边栏、评论框、分页器等等。现在不用深入看每个 include 文件，知道这个机制就行，后面章节会讲到常用的几个。

## 小结

这一章讲了三个核心：

| 文件/目录 | 一句话 |
|---|---|
| `_config.yml` | 改站点信息、作者、配色、默认行为的地方，改完要重启服务器 |
| `_posts/` | 写博客的地方，文件名必须带日期，必须有 front matter |
| `_layouts/` | 页面骨架，`single.html` 覆盖绝大部分场景，一般不需要动 |
