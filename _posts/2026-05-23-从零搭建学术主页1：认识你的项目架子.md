你从 GitHub 上 fork 了 Academic Pages 模板，打开一看——三十多个文件夹和一堆配置文件。别慌，这些目录是有规律的。

## Academic Pages 是什么？

Academic Pages 是基于 **Minimal Mistakes**（Jekyll 最流行的主题之一）的定制版，专门为学术界人士设计。和普通的 `username.github.io` 模板相比，它多了一整套学术内容管理系统：论文、演讲、教学经历、作品集，各有一套独立的目录来管理。

可以把它理解为：**普通 Jekyll 博客 + 学术 CV 管理系统**。

## 全景速览

打开项目根目录，你会看到这些东西。先别逐个点进去看，只需要记住一个分类逻辑：

**第一类：你写的内容**

| 目录/文件 | 说明 |
|---|---|
| `_posts/` | 博客文章，文件名必须带日期，比如 `2026-05-23-hello.md` |
| `_drafts/` | 草稿箱，本地预览用，不会出现在正式网站上 |
| `_pages/` | 独立页面——"关于我"、"简历"、"404"、归档页都在这里 |
| `_publications/` | 论文列表，每篇论文一个 `.md` 文件 |
| `_talks/` | 学术报告和演讲 |
| `_teaching/` | 教学经历 |
| `_portfolio/` | 项目作品展示 |
| `images/` | 博客里用到的图片 |
| `files/` | 可下载的文件（PDF、简历等） |

**第二类：决定网站长什么样的模板文件**

| 目录/文件 | 说明 |
|---|---|
| `_config.yml` | 全站配置中心——站点标题、作者信息、插件开关都在这里 |
| `_layouts/` | 页面骨架，决定"文章页"、"首页"、"简历页"各长什么样 |
| `_includes/` | 可复用的 HTML 组件——导航栏、页脚、侧边栏等 |
| `_sass/` | 样式表（SCSS），改颜色、字体、间距就来这里 |
| `assets/` | 静态资源——CSS、JS 文件 |
| `_data/` | YAML 数据文件——导航菜单结构、作者信息、CV 数据 |

**第三类：工具和构建产物**

| 目录/文件 | 说明 |
|---|---|
| `_site/` | Jekyll 构建生成的最终 HTML，**不要手动改，也不要提交到 git** |
| `markdown_generator/` | Python 脚本，可以从 BibTeX/CSV 批量生成论文页面 |
| `scripts/` | 辅助脚本 |
| `talkmap/` | 演讲地点地图可视化 |
| `.github/` | GitHub Actions 自动部署配置 |
| `.devcontainer/` | GitHub Codespaces 开发容器配置 |

## 你需要记住的三条规则

**1. 以下划线 `_` 开头的目录是 Jekyll 的"特殊目录"。** Jekyll 会按照特定规则处理它们——`_posts/` 按日期发布，`_layouts/` 当模板用，`_data/` 当数据源用。普通目录（`images/`、`files/`）则会原样复制到生成的网站里。

**2. 改内容和改样式的文件是分开的。** 写博客改 `_posts/`，换颜色改 `_sass/`，加导航项改 `_data/navigation.yml`。不需要为了写篇文章就去碰 CSS。

**3. `Gemfile` 里没有单独引入主题。** 你的项目是 Academic Pages 的完整 fork——Minimal Mistakes 的所有模板和样式都已经直接放在 `_layouts/`、`_includes/`、`_sass/` 里了。这意味着你可以直接修改这些文件来深度定制，不用担心被上游覆盖（因为你就是自己的"上游"）。

## 一个典型的改文章流程

> 我要写一篇新博客 → 新建 `_posts/2026-05-23-标题.md`
> 我要加一篇论文 → 新建 `_publications/2026-my-paper.md`
> 我要改导航栏上的链接 → 编辑 `_data/navigation.yml`
> 我要改网站标题 → 编辑 `_config.yml` 的 `title` 字段
> 网站颜色太丑了 → 去 `_sass/` 下找对应的 SCSS 文件
